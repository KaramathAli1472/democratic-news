# React + Vite

This template provides a minimal setup to get React working in Vite with HMR and some Oxlint rules.

Currently, two official plugins are available:

- [@vitejs/plugin-react](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react) uses [Oxc](https://oxc.rs)
- [@vitejs/plugin-react-swc](https://github.com/vitejs/vite-plugin-react/blob/main/packages/plugin-react-swc) uses [SWC](https://swc.rs/)

## React Compiler

The React Compiler is not enabled on this template because of its impact on dev & build performances. To add it, see [this documentation](https://react.dev/learn/react-compiler/installation).

## E-Paper uploads

The admin dashboard uploads editions to the Cloudinary account configured for
this app (`bk7v2mmu`) and stores edition metadata in the Firestore `epapers`
collection. Upload signatures are generated by a Cloudflare Worker so the
Cloudinary API secret does not need to be exposed in the browser or stored in
Firebase Functions. PDFs are uploaded as Cloudinary image assets; the public
E-Paper page displays each PDF page as an on-demand JPG transformation. The
Cloudinary account must allow PDF uploads and PDF delivery.

1. In Cloudflare Dashboard, create a Worker and paste in
   `cloudflare/epaper-upload-worker.js`.
2. For local Wrangler testing, fill `cloudflare/.dev.vars` (this file is
   git-ignored). For the deployed Worker, add these under
   **Worker > Settings > Variables and Secrets**:
   - `CLOUDINARY_API_KEY` as a secret, from Cloudinary Console > Settings > API
     Keys.
   - `CLOUDINARY_API_SECRET` as a secret, from the same Cloudinary page.
   - `GEMINI_API_KEY` as a secret for Gemini Vision story detection and matching.
   - `CLOUDINARY_CLOUD_NAME` as a variable with value `bk7v2mmu`.
   - `FIREBASE_API_KEY` as a variable, using `VITE_FIREBASE_API_KEY` from the
     local `.env`.
   - `FIREBASE_PROJECT_ID` as a variable with value `democratic-news`.
   - `ALLOWED_ORIGINS` as a comma-separated list of the exact website origin(s),
     such as `https://your-domain.example,http://localhost:5173`.
3. Deploy the Worker. Its signing endpoint is
   `https://<worker-name>.<account>.workers.dev/epaper-upload-signature`;
   its story-mapping endpoint is
   `https://<worker-name>.<account>.workers.dev/epaper-auto-map`.
4. Set `VITE_EPAPER_SIGNING_URL` and `VITE_EPAPER_MAPPING_URL` in the frontend
   `.env` to those full endpoints, then rebuild and deploy the frontend.

In E-Paper Management, use **Auto-map news** on an uploaded edition. The Worker
uses Gemini Vision to detect story rectangles on each page and match each
rectangle to the closest existing News headline. The reader renders each
detected rectangle as a link to its matched article. Keep `GEMINI_API_KEY` in
Cloudflare Worker secrets only; Gemini API usage may incur charges.

Do not put `CLOUDINARY_API_SECRET` in `.env`, frontend variables, or chat. The
`ml_default` Cloudinary upload preset must be enabled for this Cloudinary
account.
